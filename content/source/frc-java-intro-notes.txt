3. Subsystems — The Basics
Open the ExampleSubsystem  to see the standard structure:
• Constructor  — public ExampleSubsystem()
• periodic()  — runs every 20 milliseconds , continuously, unless a condition pauses it
(rarely happens). Think of it like Arduino/Romi loop() .
• simulationPeriodic()  — only for simulations, ignore for us.
What a subsystem does:  It's what interacts with the motors . When you want to turn a
motor on, you do it through a subsystem.
Making our drivetrain subsystem

Declaring motors
At the top of the class  (right under public class DrivetrainSubsystem ), declare your
motor variables.
The syntax follows normal Java variable creation — type → name → value :
• SparkMax  is provided automatically once RevLib is installed — when you type
SparkMax  and let autocomplete ﬁll it in, the import is added for you.
• First argument = the device ID  (don't make them all 0  — give each a unique ID).
• Second argument = the motor type : MotorType.kBrushless .
• If the motor type doesn't auto-import, retype Mo...  and pick MotorType  from
autocomplete.
Brushed vs. brushless:  Brushed motors are the older type; brushless  are the newer ones
we actually use (e.g., Krakens). We almost always use brushless.
How many motors / why four
The ChairBot has two sides , with two wheels per side , and two motors driving each side .
So we declare four motor variables total : two left, two right.

5. Methods to Control the Motors
At the bottom of the subsystem , create methods to set motor speeds.
• public void  because we're not returning anything .
• Takes in a double speed  parameter.
• Speed range is −1.0 to 1.0  (negative = reverse, positive = forward).
• Use the fundamental .set()  call on each motor.
Big takeaway: motor.set(speed)  is the  fundamental call. If you understand .set() ,
you're already about a third of the way to making a robot move. Note that a method does
nothing until it's actually called  — declaring it just deﬁnes the behavior.
Subsystem structure recap:  variables (your motors) at the top → methods (set-left / set-
right) at the bottom that take in a value sent from RobotContainer  and apply it to the
motors.

Ports & the Driver Station
• The port number maps to a slot in the Driver Station application  (not the laptop itself
— the FRC Driver Station app on Windows).
• In the Driver Station's controller/USB section , you drag and drop  your plugged-in
controller into a port (usually port 0 ).
• When the code initializes the controller variable with port 0 , it reads inputs from
whatever is assigned to port 0 in the Driver Station.
• Ports identify the controller, not individual buttons.  Which button you read is
handled in code (below), not by ports.
7. Constants — Why Use Them
In the project template you'll see something like
OperatorConstants.kDriverControllerPort  instead of a raw 0 .
java
// Plain — reads state:
PS5Controller  joystick = new PS5Controller ( 0 ) ;
// Command-based — triggers commands:
CommandPS5Controller  joystick2 = new CommandPS5Controller ( 0 ) ;

===== PAGE 6 =====
• A constant  is just a stored value (e.g., kDriverControllerPort = 0 ) in
Constants.java .
• Why bother instead of typing 0 ?  If multiple controllers/ﬁles use that port and you
later need to change it, you'd have to hunt down and edit every 0  by hand. With a
constant, you change it once  in Constants.java  and it updates everywhere it's
referenced.
• This is the textbook use-case for the constants ﬁle: a value used in multiple places that
rarely changes.
8. Binding Buttons to Actions
In RobotContainer 's conﬁgure bindings  area, you bind a button to an action.
Pattern
controller.button().condition(commandToRun)
Conditions you'll care about  (ignore the rest):
• onTrue  — ﬁres once when the button becomes pressed
• onFalse  — ﬁres once when released
• whileTrue  — runs while held down
• whileFalse  — runs while not held
Side note: cross()  is the PS5 "X" button. (Y es, there was confusion between "the cross"
button and "lacrosse" on the call.)

Most of the time you won't have a pre-made command — you'll just have subsystem
methods like setRightMotors . To run one on a button press, wrap it in an
InstantCommand  using a lambda :
What a lambda is:  a small function you can write inline, on the spot, in a single line of code
( () -> ... ).
What InstantCommand  does:  Commands normally need an ending condition. An
InstantCommand  runs once and immediately ends . That makes it perfect for sequences  —
e.g., turn on rollers (instant) → then the next step ﬁres immediately after, like in a shoot or
intake sequence.
9. Full Signal Flow (Controller → Motor)
Putting it all together, here's how a press travels through the code:
1. Initialize a CommandPS5Controller  (mapped to a Driver Station port).
2. Button is pressed → its state changes to true .
3. onTrue  ﬁres an InstantCommand .
4. The InstantCommand 's lambda calls mDrivetrain.setLeftMotors(1) .
5. Inside setLeftMotors , speed  is set to 1 , and .set(1)  is applied to each left motor.
6. All left motors now run at full power and keep running at that speed  until it's
changed.
Repeat the same pattern with diﬀerent buttons and diﬀerent speeds/methods for full
control.
That's the whole fundamental loop.  The advanced stuﬀ (PID, feedforward, control theory)
sits on top of this — but if you understand the above, you could technically make the robot
move (just not smoothly yet).

Key Terms Cheat Sheet

===== PAGE 9 =====
• Subsystem  — class that interacts with hardware (motors). V ariables at top, methods
at bottom.
• periodic()  — runs every 20 ms continuously.
• SparkMax  — the motor controller we used (needs RevLib installed).
• Brushless ( kBrushless )  — the newer motor type we use; brushed is the old one.
• .set(speed)  — the fundamental command to drive a motor; speed is −1.0 to 1.0.
• PS5Controller  — reads button state .
• CommandPS5Controller  — runs commands  on button state changes (used most
often).
• Constant  — a reusable stored value (e.g., a port number) you change in one place.
• Lambda  ( () -> ... ) — an inline single-line function.
• InstantCommand  — a command that runs once and immediately ends; great for
sequences.
• NetworkTables  — how a computer sends data to the robot (used in the voice-
command experiment).
